# GitHub 更新机制

## 入口和更新源

“关于 → 检查更新”打开应用内部更新页。更新页从下列地址读取最新正式 Release 的 `update.json`：

```text
https://github.com/cxcboss/kuwo-music-car/releases/latest/download/update.json
```

GitHub 的 `latest` 跳过草稿和预发布版本。项目不提供原厂 APK 检测入口，也停止原厂 RFix 远程补丁初始化。更新检测不需要 GitHub Token，不在应用冷启动期间运行。

## 清单合同

```json
{
  "schemaVersion": 1,
  "applicationId": "cn.kuwo.kwmusiccas",
  "versionName": "1.0.0",
  "versionCode": 74000,
  "fileName": "1.0.0-酷我音乐.apk",
  "size": 93036000,
  "sha256": "94a87504ef59edd0bcf65eeb3c9ec013a43cdbc69ee3192a9bfe2fbed9b83b77",
  "downloadUrl": "https://github.com/cxcboss/kuwo-music-car/releases/download/v1.0.0/1.0.0-%E9%85%B7%E6%88%91%E9%9F%B3%E4%B9%90.apk"
}
```

上例用于说明字段，字节数和哈希随实际构建变化；发布时只能使用构建脚本生成的 JSON。版本比较使用 `versionCode`，不按字符串或浮点数比较显示版本。新的版本码更高才提供下载。

外部清单在读取处检查格式、包名、文件名及本仓库 HTTPS 下载 URL。下载流直接写入 `.part` 文件并计算 SHA-256。完成后核对长度和哈希、APK 包名/显示版本/版本码、与已安装应用相同的签名证书，最后改名为 `.apk`。

## 下载和安装兜底

固定保存位置：

```text
/storage/emulated/0/000/酷我音乐更新/版本号-酷我音乐.apk
```

这里对应文件管理器的“内部存储/000/酷我音乐更新”。不转存到应用缓存或私有 Download 目录。Android 6–10 按需申请存储权限；Android 11+ 按需打开所有文件访问授权页。未获得权限时显示失败状态，不静默改变下载位置。

下载完成后通过现有 FileProvider 生成 content URI，并授予系统安装器临时读取权限。优先使用 `ACTION_INSTALL_PACKAGE`，设备没有匹配安装器时改用 `ACTION_VIEW`；需要时引导开启本应用安装来源权限。系统安装确认仍由系统处理。

无论安装成功、取消或安装器不可用，完整 APK 都保留在上述目录，方便用户通过文件管理器手动安装。失败或中断的 `.part` 文件不作为安装包使用。

## 发布一致性

每个正式 Release 使用 `v版本号` 标签，至少包含：

- `版本号-酷我音乐.apk`
- `update.json`
- `SHA256SUMS`

同一标签不得替换成另一份 APK。修复后递增版本并发布新标签，保持签名证书不变。不要把源码 ZIP 当作更新包。
